深度学习系统（三）：大模型训练、推理与服务

1. 预训练、微调与人类对齐

1.1 各阶段在学什么

阶段 数据与目标
预训练 网页、书籍、对话等通用数据，以及代码、科学、多语等专用数据；学习通用语言与知识表示
SFT / 指令微调 人工或半自动构造的“指令—回答”示例，学习按要求完成任务
人类对齐 / RLHF 利用偏好反馈进一步调整回答行为；通常包含初始训练、收集反馈、强化学习并迭代
提示与任务定制 用模板、示例和领域信息组织任务输入，不一定更新模型权重

预测下一个 token、预测遮挡内容等属于从数据自身构造监督信号的自监督学习。

预处理要考虑清洗、去重、格式统一与敏感信息处理。常见预训练目标包括：自回归语言建模、只对后缀计损失的前缀语言建模、中间填充 FIM；模型学习什么，与损失计算覆盖哪些位置有关。

1.2 参数高效微调

方法 核心思路
LoRA 冻结原权重，用两个小矩阵表示低秩增量；推理时在适用情况下合并回权重
AdaLoRA 动态分配不同权重更新的秩预算
Prefix Tuning 在注意力的 K/V 前加入可训练连续前缀
Prompt Tuning 在输入表示前加入可学习的连续提示向量

设原权重 W₀ 为 d_out×d_in，低秩维度 r 远小于这两个维度，取 B 为 d_out×r、A 为 r×d_in：

\[ W=W_0+BA,\qquad P_{trainable}=r(d_{in}+d_{out}). \]

低秩分解的字母约定可以不同，矩阵形状决定相乘次序。LoRA 主要减少可训练参数、梯度和优化器状态，基础模型权重与前向激活仍有开销。

2. 分布式训练：并行、显存与通信

2.1 三类并行与基本术语

并行方式 切分对象 主要代价
DP 数据并行 每卡相同模型，不同样本批次 同步梯度；普通 DP 不减少每卡模型副本
TP 张量并行 将同一层的矩阵 / 张量分到多卡 层内需要频繁通信
PP 流水线并行 按层或阶段切模型 传激活与反向梯度；负载不均和流水气泡
3D 混合并行 组合 DP、TP、PP 需要同时考虑负载、显存和拓扑

进程、Rank、Device、通信域不能混为一谈：常见映射是一进程一设备；Rank 是某通信组中的成员编号；通信域规定哪些成员一起做集合通信。逻辑上相邻的 Rank，不一定物理相邻。

模型装不下、每秒吞吐不足、总训练时间太长，是扩展多卡的不同动机。一般先利用机内高速互联，再考虑跨机网络；高频 TP 通信应尽量放在高速互联域内。

2.2 减少内存的手段

  • Gradient Checkpointing / 重计算：少存部分激活，在反向时重算，用计算换显存。
  • 混合精度：减少部分张量的字节数，同时关注数值稳定。
  • ZeRO：逐阶段分片优化器状态、梯度、参数，减少普通 DP 的重复保存。
  • Offload：把部分状态卸载到 CPU / 主机内存等，换来额外传输；如 ZeRO-Offload、ZeRO-Infinity。

DeepSpeed 提供相关内存优化和并行能力；Megatron-LM 侧重张量切分等大模型并行。选择方案时，既要看装得下，也要看通信与重计算是否拖慢训练。

3. 推理：加载、执行、缓存与解码

3.1 LLM 的 Prefill 与 Decode


两阶段的输入长度和复用方式不同。

阶段 计算与状态 主要关系
Prefill 并行处理提示中的多个 token，建立初始 K/V 缓存 影响首 token 时间
Decode 复用历史 K/V，为新位置计算 Q/K/V，通常每轮生成一个 token 影响后续 token 间隔

KV Cache 缓存的是各层历史 K、V。它减少重复投影与历史部分的重复计算，代价是随序列与并发增长占用显存；每轮新 Query 仍需要和可见的历史信息做注意力计算。

3.2 从 logits 选 token

策略 做法与取舍
Greedy 取最高分 / 最高概率 token，快，但可能单调或重复
Temperature 改变分布集中程度；温度越高，通常越分散
Top-k 只在最高概率的 k 个候选中，按重新归一化后的概率采样
Top-p 按累计概率阈值保留候选，再采样
Beam Search 维护多个高分候选序列，逐步扩展；比贪婪搜索覆盖更多路径，但成本更高

Top-k 是限制候选集合，不是要求在 k 个词中均匀随机抽取。自回归生成把选出的 token 加回上下文，再继续下一步。

4. 推理优化：每种方法在节省什么

4.1 量化与低精度

量化用更低位宽表示权重或激活，减少存储与数据搬运，并在硬件、Kernel 支持时加速。QAT在训练中考虑量化影响，PTQ在训练后通过校准等方式完成量化。

对称量化常把实数零对应到整数零；非对称量化还使用零点偏移来适配区间。量化公式中的 scale、zero point 与通道 / 分组粒度都会影响误差与执行成本。

方法 重点
AdaQuant 逐层校准，减少量化层与全精度层输出的差异
BRECQ 按网络块重构，考虑跨层依赖，并利用二阶误差 / Fisher 信息近似评价重要性
LLM.int8() 向量级量化；异常特征维度走较高精度，其余走 INT8 的混合精度分解
CPU INT4 推理 量化算法、粒度、group size 与 INT4 Kernel / Runtime 协同；可结合 GPTQ、AWQ 等量化方法与 AVX、VNNI、AMX 等指令支持

4.2 Orca：把调度粒度降到每次迭代

静态批处理要求同批请求相互等待：短请求结束后占位，新请求也难插入。Orca 在迭代级重新组批，已结束请求退出，新请求进入，提高资源利用与响应效率。

Linear 等操作可合并 batch 与序列维度；Attention 则按请求组织各自的历史上下文，再合并结果。不同请求长度和阶段不同，不能简单当成完全相同的张量。

4.3 PagedAttention：减少 KV 内存浪费


借鉴操作系统分页思想，物理块无需连续分配。

为每个请求预留最大生成长度，会产生浪费和碎片。PagedAttention 将 KV 分成固定 token 数的块，用映射表连接逻辑块与物理块，按需分配和释放。

分页中的对应关系是：请求像进程，逻辑 KV Blocks 像虚拟页，物理 KV Blocks 像物理页，token 数据像页内字节。分页优化管理方式，不会消除保存 K/V 本身需要的字节数。

忽略并行切分，KV 缓存大小可按 2 × 层数 × 批次 × 序列长度 × KV头数 × 每头维度 × 每元素字节数 估算。40 层、KV 总维度 5120、FP16 时，每 token 约 0.8 MB；GQA 应按实际 KV 头数重新计算。

4.4 StreamingLLM：保留“汇聚注意力”的初始位置

完整密集 Attention 的上下文成本高；只保留最近窗口又可能导致质量下降。Attention Sinks 指初始少量 token 在注意力分布中起特殊作用。

StreamingLLM 组合初始 sink token 的 KV、最近窗口的 rolling KV，以及当前 token，并处理窗口位置与位置编码的对应。例如，可保留 4 个初始位置。能持续接收流式输入，不代表模型能检索已从窗口删除的任意遥远内容。

4.5 推测解码：小模型起草，大模型验证

草稿模型 q 连续提出 γ 个 token，主模型 p 并行核验；接受前缀，遇到第一个拒绝位置时按修正分布重新采样。一次主模型调用可输出 1 到 γ+1 个新 token。

为了保持主模型的采样分布，候选 x 按 min(1,p(x)/q(x)) 接受；拒绝后从归一化的 max(0,p−q) 分布补采样。接受部分贡献 min(p,q)，补偿部分贡献 p−min(p,q)，合起来仍是 p。保持分布依赖正确的接受与补偿规则，不能简单把大模型认为“不够好”的词随意替换。

5. 从模型推理到完整服务

5.1 应用系统的三个模块

模块 组成与职责
数据预处理 / Embedding 采集、加载、解析数据，生成向量并保存到向量库
Prompt 构建 / 检索 组合模板、少量示例、外部 API 信息和检索文档
Prompt 执行 / 推理 调用模型，附加缓存、日志、验证和应用托管

这里的检索增强是在推理输入中加入相关资料，不等于把资料重新训练进权重。LLM Cache 与 KV Cache 也不同：前者可缓存应用请求 / 回答，后者保存模型内部注意力历史。

5.2 vLLM：Scheduler、KV 管理器与模型执行器

vLLM V1 的执行流程为：加载模型并估算 KV 容量，初始化 Scheduler / KV Manager / ModelExecutor，按每轮 token 预算组织执行。运行中和等待中的请求、分块 Prefill、Decode 可以在调度中共同出现；资源不足时可能等待或抢占。

例如，3 个 prompt 长度为 3、5、12，每轮 token 预算为 10：

轮次 r1 / r2 / r3 的处理量 含义
Step 0 3 / 5 / 2 r1、r2 完成提示处理，r3 还剩 10 个 prompt token
Step 1 1 / 1 / 8 前两者 Decode，r3 继续 Prefill
Step 2 1 / 1 / 2 r3 完成剩余 Prefill
Step 3 1 / 1 / 1 三者共同 Decode

表中的数字是调度的 token 工作量，不能把 r3 的 8 个 Prefill token 误读为生成了 8 个输出 token。大模型还可按张量并行跨卡执行，KV 块由管理器按需分配和回收。

5.3 MLC LLM 与可靠服务

MLC LLM 通过编译与 MLCEngine 面向多平台部署，本地运行支持离线使用、定制与应用嵌入。

服务的可靠性还涉及长任务推理与协作、多模态与动态场景、高效推理与规模服务、智能体权限和提示注入、幻觉偏见隐私，以及持续评测与治理。可靠性要靠过程检查、失败恢复、权限控制、监测和反馈闭环共同实现。
