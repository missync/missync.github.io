深度学习系统（一）：系统组成与执行流程

本文最后更新于 2026年10月30日 凌晨

1. 为什么需要深度学习系统

深度学习系统连接算法与硬件，承载模型训练、推理和部署。会描述一个模型，还需要让它在实际设备上算得动、跑得快、稳定提供服务。

AI 产业的四个要素是数据、算法、算力、场景。模型和数据扩大后，系统要解决三类约束：显存容量能否容纳模型状态，存储带宽能否及时供数，多卡通信能否跟上计算。

1.1 智能计算系统的演进

课件引用陈云霁对智能计算系统的三代划分，作为理解发展方向的一种视角：

  1. 第一代：面向符号主义。 以 Lisp 机、Prolog 机为例，硬件支持符号处理和高层语言执行。
  2. 第二代：面向连接主义。 围绕神经网络的大规模数值计算，形成 CPU 与 GPU、NPU 等加速器协作的异构系统，也是本课程重点。
  3. 第三代：通用智能载体的展望。 探索在大规模虚拟环境中让智能主体通过交互学习，涉及计算架构、算法及跨学科协同。这是课件中的研究设想。

深度学习的实际应用与产业需求推动专用计算；通用处理器性能增长放缓、模型开销扩大，则进一步推动软硬件协同设计。

1.2 从云到边、端

  • 云端：数据中心与集群，侧重规模、吞吐和并发服务。
  • 边缘：靠近数据源，强调低时延、网络条件和现场处理。
  • 端侧：手机、嵌入式及 IoT 设备，受功耗、体积、存储和离线条件约束。

部署位置会影响模型规模、压缩方式和运行时选择。课件还提到混合位宽量化、模型压缩、架构搜索、轻量运行时，以及在线学习和联邦学习等方向；这些方案分别对应资源适配或数据使用方式，不能互相替代。

2. 全栈分层：每一层负责什么

层次 核心职责
算法 定义任务、模型、损失与优化目标
框架 张量与网络表达、自动微分
编译 图优化、算子融合、设备代码生成
运行时 内存、任务调度、同步与通信
硬件 计算单元、存储层次、互联

部署服务贯穿模型加载、请求处理、执行调度、版本管理与监测，建立在上述各层之上。

2.1 从任务到可执行程序

课件以风格迁移串起五步：输入 → 建模 → 实现 → 运行 → 输出。先约定数据与目标，再选择网络，用框架表达计算，将模型映射到设备，最后把数值结果转成图像等任务输出。

执行路径可进一步展开为 Layer → Operator → Kernel → 指令。框架表达“算什么”；编译器通过中间表示（IR）、图变换、布局选择和算子实现决定“怎样算”；运行时负责按依赖执行。

一个算子不一定对应一个 Kernel。 多个算子可以融合，一个复杂算子也可由多个 Kernel 完成。课件用 TVM 展示图优化、张量计算表达、调度优化、后端代码生成与轻量运行时之间的联系。

3. 张量、算子与计算图

张量要同时看 shape、维度语义、dtype 和内存布局。 图像常用 NCHW，自然语言表示常用批次×序列×特征；点云、图等还涉及稀疏张量。相同元素数，不代表相同语义或相同物理访问效率。

计算图用节点表示算子、边表示张量依赖；自动微分构造反向计算。动态图边运行边建立依赖，便于调试；静态图先构建 / 编译再执行，有更大的全局优化空间。现代框架通常兼具即时执行与图捕获：如 torch.compile、tf.function、MindSpore Graph / PyNative、jax.jit、Paddle 动转静。

分支和循环可由宿主语言、控制流原语或源码解析表达。展开后的单次执行可按依赖调度；包含循环的完整程序表达不能简单等同于一张固定 DAG。运行时根据就绪依赖组织执行，图捕获失败处可能出现 graph break。

反向图从损失出发，调用各算子的梯度规则。它常需要前向中间量：ReLU 的反向需要判定输入是否大于零，卷积的权重梯度需要输入，输入梯度需要权重。保存激活及梯度等状态，是训练比纯推理更占显存的重要原因。

4. 训练：数据、损失、梯度与评估

4.1 数据准备与划分

先解码、归一化并对齐 shape / dtype，再按需要打乱训练样本、组成批次。记录随机种子、划分规则、数据版本及预处理配置，使实验可复现。

数据子集 用途
训练集 计算梯度并更新参数
验证集 选超参数、早停时机和 Checkpoint
测试集 训练与调参结束后的最终评估

验证和测试均不更新参数；反复根据测试结果改模型，会使测试集失去独立评估作用。

4.2 一次训练 step

  1. 前向：批次输入得到 logits，分类任务通常用交叉熵形成标量损失；需要时加入正则项。
  2. 反向：自动微分得到各可训练参数的梯度，梯度与对应参数形状一致。
  3. 更新：SGD 使用当前梯度；Momentum、Adam 结合历史状态决定更新量。

一个 epoch 是遍历一轮训练数据，各批次分别执行 step。训练损失下降说明正在拟合训练数据，还须查看验证表现；验证损失回升可能提示过拟合，NaN / Inf 则需要检查数据、学习率及数值稳定性。

4.3 MNIST：把全过程连起来

课件的 MindSpore 示例使用 28×28 灰度图、10 个类别，原始数据含 60,000 张训练图和 10,000 张测试图。数据先按 1/255 缩放，再用均值 0.1307、标准差 0.3081 归一化，执行 HWC→CHW 和标签类型转换。

  • 输入：批图像 [64,1,28,28] Float32，标签 [64] Int32。这是该示例的接口约定。
  • 网络：Flatten → 784→512→512→10，隐藏层使用 ReLU，输出 logits 为 [64,10]。
  • 参数：各全连接层含偏置，共 401,920 + 262,656 + 5,130 = 669,706 个。
  • 训练与评估：示例用交叉熵及学习率 0.01 的 SGD；评估模式下累计损失、正确数，不更新参数。
  • 保存与恢复：保存 Checkpoint，恢复同结构网络，检查参数匹配，再核对预测结果。

单图推理保留批维 [1,1,28,28]。把 batch size 从 64 改成 32，输入、标签和 logits 的第一维会变，网络参数量不变。省略 HWC→CHW 可能破坏通道约定；应从数据形状与网络接口定位问题。

5. 推理：从训练产物到任务结果

模型加载 → 输入预处理 → 前向执行 → 输出解码。 加载时要对齐结构、参数键与 shape、dtype、设备、驱动和运行时；切到评估模式并按推理需要关闭梯度，随后预热，避免把首次编译与内存初始化混入稳定性能。

训练与推理应使用一致的输入约定。分类输出取 argmax / top-k；检测还要处理阈值与坐标，分割要恢复掩码，数值张量经过解码才成为任务结果。

Checkpoint、MindIR 等产物各有加载路径。分布式 Checkpoint 可按进程保存并在支持时重分片；Safetensors 保存张量权重，模型结构与配置另行提供，文件本身也可能分片。文件能读、参数能装载、模型行为正确，是三层不同的检查。

模型版本还需与类别映射、Tokenizer 等配套。eval 改变 Dropout、BatchNorm 等模块的行为；关闭梯度则减少自动微分开销，两者职责不同。

6. 性能评测与优化闭环

模型参数或 FLOPs 更少，不一定实际更快。算子实现、布局、访存、启动、同步和通信都会影响结果。

课件列出 MLPerf、BenchIP 等评测体系。比较结果前，应统一任务、模型质量要求、输入规模、数据精度、硬件软件版本和计时边界，再分别看时延、吞吐、显存与能耗。

实践流程是 跑通正确性基线 → Profiling 定位瓶颈 → 分析算子与硬件约束 → 修改一项 → 端到端复测。架构分析同时关注运算单元、存储层次、指令集、编程框架与多处理器组织，课件举例包括 TPU、Eyeriss。

具体的 Roofline、通信模型和在线服务指标见算力架构与性能分析；平台开发与实验路线见昇腾技术栈。
