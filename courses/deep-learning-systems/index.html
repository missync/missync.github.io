深度学习系统：从模型到昇腾软硬件的课件复习

本文最后更新于 2026年10月26日 凌晨

本文整理杨建磊老师《深度学习系统》目录下的三讲课件、2026 课程大纲，以及“昇腾体系化课程”中的 V00 和 V01，共 6 份、616 页。按知识主题合并重复页，用概念、速查表、少量公式与原图帮助复习。硬件数字和模型配置按课件示例解释，不把某个型号或版本推广到所有平台。

模型： 系统全景 · 神经网络与训练 · CNN · 语言模型与生成模型 · Transformer · MiniMind

训练与服务： 预训练、微调与对齐 · 并行训练与显存 · 推理流程 · 推理优化 · 服务架构与 vLLM

硬件与系统： CPU、GPU 与 DSA · 昇腾 AI Core 与数据流 · 开销估算与性能模型 · 线上性能指标 · 平台、实验与后续主题 · 勘误与课件索引

基础概念可配合《深度学习基础与应用》复习篇阅读。建议先看各节的加粗结论与表格，需要回忆计算过程时再看公式和例子。

1. 系统全景：模型背后有什么

来源：第一讲第 7–14、20–51 页；V00 第 7–24 页；V01 第 6–18 页。

深度学习系统连接算法应用与计算硬件，承载训练、推理和部署的完整生命周期。 研究对象包括计算框架、编译器、运行时、算子库、内存、通信、调度与加速器，评价也从准确率扩展到耗时、吞吐、内存、能耗与成本。


图：V01 第 6 页。课件以六层组织模型从代码走向部署的路径。

层次 主要职责
算法与应用 定义任务、模型、损失和优化目标
框架 提供模型组件、张量操作、计算图和自动微分
编译 捕获图、图优化、算子融合、选择实现并生成代码
运行时 内存管理、依赖调度、任务队列、同步与通信
硬件 计算单元、存储层次、片内与片间互联
部署 导出、压缩、服务封装、版本管理与运行监控

一层 Conv2D 会进一步下沉为算子 → Kernel → 矩阵计算 / 多层循环 → 指令。模型层表示计算语义，Kernel 是落到具体设备的实现，两者不必一一对应，融合后多个算子可能共用一个 Kernel。

1.1 为什么需要系统视角

模型、数据和请求规模增长，逐渐暴露内存墙、通信墙、调优墙、开发墙。提高精度的算法如果导致无法装入显存、难以并行或部署成本过高，需要重新权衡。课件因此强调应用驱动、全栈贯通和软硬件协同。

系统形态从数据中心、超级计算机延伸到 PC、手机、嵌入式和 AIoT；端、边、云对资源与时延的要求不同。TinyML 关注受限设备上的高效智能；PIM（存内处理）、CIM（存内计算）等方向尝试缓解存储与计算分离带来的搬运开销。

1.2 三代智能计算系统的课件划分

第一代面向符号主义，如 LISP / Prolog 专用机；第二代面向连接主义和深度学习，是本课程主要对象。前者受应用需求、成本和通用处理器快速进步限制，后者已有大量工业应用，并受益于数据、算法和算力的发展。

课件关于“第三代系统作为通用智能发育的沙盒”、海量智能体和多学科交叉的讨论，属于一种参考分类与研究展望，不应当作已经成立的 AGI 实现方案。

2. 神经网络、反向传播与训练流水线

来源：第二讲第 3–39 页；V01 第 19–89 页。

2.1 从函数到神经网络

神经元将输入加权求和，再经过非线性函数；多层嵌套形成复杂映射。M-P 模型提供了早期抽象，MLP 由输入、隐藏和输出层构成，层间通常全连接。适当条件下、足够宽的非线性网络具有通用逼近能力，这不保证有限数据下容易训练或一定泛化。

模型 主要组织方式或擅长的结构
MLP 全连接特征变换，主要计算是 GEMM
CNN 局部连接与参数共享，处理空间局部结构
RNN / LSTM 隐藏状态随时间传递，处理序列；LSTM 通过门控保留或遗忘信息
GNN 沿图结构组织节点信息的计算

2.2 反向传播求梯度，优化器更新参数

前向传播逐层计算预测及损失；反向传播从损失出发，沿反向依赖使用链式法则求各参数的梯度；优化器再根据梯度更新参数。

设输出 o 由中间量 a 决定、a 依赖权重 w，Sigmoid 的值为 σ(z)：

\[ \frac{\partial L}{\partial w} =\frac{\partial L}{\partial o} \frac{\partial o}{\partial a} \frac{\partial a}{\partial w},\qquad \sigma'(z)=\sigma(z)(1-\sigma(z)),\qquad w\leftarrow w-\eta\frac{\partial L}{\partial w}. \]

隐藏层同时影响多个下游输出时，需要把各条路径的梯度贡献相加。第二讲用两个输入、两个隐藏神经元、两个输出的例子手算；取学习率 0.5 更新后，总误差从约 0.2984 降到 0.2910。

课件的两段 NumPy 代码使用了不同误差信号符号：y−prediction 配合加法更新，与 prediction−y 配合减法更新可以表示同一负梯度方向。不能只看 += 就断言在做梯度上升；代码中的 xrange、个别变量拼写是旧语法或笔误，复习重点是矩阵形状和更新方向。

2.3 深层网络的困难与对应技术

困难 / 技术 核心知识点
梯度消失 / 爆炸 多层导数连乘可能过小或过大，前层难更新或训练不稳定
Sigmoid / Tanh 有饱和区，反向梯度可能很小
ReLU 及变体 max(0,x) 在正区间保持梯度，计算简单；课件另列 Leaky ReLU、PReLU
BatchNorm / LayerNorm 前者按批次统计相应特征，后者按单个样本 / token 的特征维度归一化，帮助稳定训练
Dropout 训练时随机关闭部分神经元，减少过度依赖
L1 / L2 正则 在损失中加入权重绝对值 / 平方惩罚，限制复杂度
Early Stopping 用验证误差决定何时停止，避免只追求训练误差
Xavier / He 初始化 控制前后层信号尺度；He 的常见方差为 2/fan_in
Adam 利用梯度的一阶、二阶矩自适应调整更新尺度；仍需要合适的学习率

学习率过小会慢，过大可能震荡或不收敛。累积 BP 按一组样本汇总误差 / 梯度；评价过拟合需同时看训练与验证表现。

2.4 张量、算子与计算图

训练范式还要区分：监督学习使用带标签映射；无监督学习从数据中发现结构，课件举 K-means、PCA；自监督学习从数据构造目标，课件举 BERT、MAE 的遮挡预测。

张量要同时看 shape、维度语义、dtype 和内存布局。 图像常用 NCHW，自然语言表示常用批次×序列×特征；点云、图等还涉及稀疏张量。相同元素数，不代表相同语义或相同物理访问效率。

计算图用节点表示算子、边表示张量依赖；自动微分构造反向计算。动态图边运行边建立依赖，便于调试；静态图先构建 / 编译再执行，有更大的全局优化空间。现代框架通常兼具即时执行与图捕获：课件列出 torch.compile、tf.function、MindSpore Graph / PyNative、jax.jit、Paddle 动转静。

分支和循环可由宿主语言、控制流原语或源码解析表达。展开后的单次执行可按依赖调度；包含循环的完整程序表达不能简单等同于一张固定 DAG。运行时根据就绪依赖组织执行，图捕获失败处可能出现 graph break。

2.5 MNIST 案例串起训练、评估与恢复

V01 的例子：60,000 张训练图、10,000 张测试图，28×28 灰度、10 分类。处理包括 1/255 缩放、按课件均值与标准差归一化、HWC→CHW、标签转 Int32、分批。

对象 课件形状 / 流程
batch 图像 / 标签 [64,1,28,28] Float32 / [64] Int32
网络 Flatten → 784→512→512→10，隐藏层 ReLU
参数量 401,920 + 262,656 + 5,130 = 669,706
logits [64,10]，接交叉熵得到标量损失
一次 step 前向与 loss → 自动求梯度 → SGD 更新，课件学习率 0.01
一个 epoch 遍历各批次，各执行一次训练 step
评估 切换评估模式，累计损失与正确数，不更新参数
保存 / 恢复 保存 Checkpoint；恢复同结构网络，检查未匹配参数，再核对预测

单张图推理仍需保留 batch 维 [1,1,28,28]。Batch Size 改变会改变批张量和 logits 的第一维，不会改变这套网络的参数数量。

3. CNN：局部连接、形状推导与矩阵加速

来源：第二讲第 41–63 页。

3.1 卷积、激活、池化与全连接

卷积核只看局部区域，并在不同空间位置共享权重；逐层形成从边缘、纹理到高层语义的表示。一次输出是局部输入与核权重逐元素乘后求和，再加偏置。

参数 / 层 含义
Kernel 高宽 一次处理的空间范围
输入通道 / filter 深度 标准卷积的每个 filter 覆盖所有输入通道
filter 数目 输出通道数
Padding 边界补值，课件主要讨论补零
Stride 卷积核每次移动的距离
Activation 逐元素加入非线性
Pooling 局部最大值 / 平均值聚合，实现下采样、减少后续开销并扩大后续感受范围
FC 将提取到的特征映射为最终类别分数

不考虑 dilation，核为 Kₕ×K𝑤、输入高宽 H×W、填充 P、步长 S 时：

\[ H_{out}=\left\lfloor\frac{H+2P-K_h}{S}\right\rfloor+1, \quad W_{out}=\left\lfloor\frac{W+2P-K_w}{S}\right\rfloor+1, \quad P_{conv}=C_{out}(C_{in}K_hK_w+1). \]

最后一式含每输出通道一个偏置。课件练习：输入 [64,3,32,32]、16 个 3×3 核、无填充、步长 1，输出为 **[64,16,30,30]**，参数量 448（不含偏置为 432）。

3.2 LeNet 风格计算流程

课件使用含 ReLU、MaxPool 的教学配置，不应与历史原版 LeNet-5 的每个细节完全等同。

阶段 输出形状
输入 32×32×1
5×5 Conv，6 个核，s=1，p=0；ReLU 28×28×6
2×2 MaxPool，s=2 14×14×6
5×5 Conv，16 个核；ReLU 10×10×16
2×2 MaxPool 5×5×16
Flatten、FC 400 → 120 → 84 → 10

若输入改成 28×28，按同样顺序得到 24→12→8→4，展平维度是 4×4×16=256。

3.3 卷积为什么能转换成 GEMM

直接卷积可用 batch、输出通道、输出高宽、核高宽、输入通道等七重循环表达。课件指出卷积在典型 CNN 中计算占比很高，但具体占比依网络而变。

im2col 将各滑动窗口展开为列，将卷积核展平为行，再执行高效矩阵乘：若输入通道为 C、核为 R×S、输出空间为 E×F、输出通道为 M，则矩阵形状为 **(M×CRS) · (CRS×EF) = M×EF**，之后 reshape 为特征图。


图：第二讲第 62 页。显式展开会重复存储窗口重叠部分，课件进一步提出 Implicit GEMM 的调研问题。

关键系统取舍是：利用成熟 GEMM 的吞吐与数据复用，同时控制显式展开带来的内存和搬运成本。

4. 语言模型、规模化与其他生成模型

来源：第二讲第 65–78 页；第三讲第 3–18 页。

阶段 / 模型 核心思路与局限
N-gram 根据最近 n−1 个词估计下一个词，简单可解释；固定窗口、组合爆炸与数据稀疏限制能力
Word2Vec / Embedding 将离散词映射为连续向量，用上下文学习语义关系
RNN / LSTM 通过隐藏状态或门控传递历史信息；长距离依赖和逐步计算限制并行
Transformer 用 Attention 直接建立 token 间依赖，训练中的序列位置可并行处理
预训练语言模型 大规模预训练学习通用表示，再适配下游任务
大语言模型 扩展参数、数据和训练计算，支持更通用的理解、生成与任务求解

Scaling Law 是性能与规模之间的经验规律。 课件把某些任务在规模区间的明显非线性提升称为“涌现”；它描述评测现象，不能理解为“参数越大，每种能力都必然出现”。

Transformer 路线 典型模型与用途
Encoder-only BERT、RoBERTa；双向上下文表示、分类与实体识别等
Encoder-Decoder 原始 Transformer、T5、BART；翻译、摘要等序列变换
Decoder-only GPT、LLaMA 等；因果自回归生成

课程还介绍两个扩展：扩散模型训练时逐步加噪、学习反向去噪，生成时从噪声出发恢复图像等内容；CLIP分别编码图像与文本，通过对比学习拉近匹配样本、对齐不同模态的表示。

相关应用包括问答、翻译、对话、文本与代码生成、bug 检测，以及图像、音频、视频的理解与生成。基础模型、开发工具和应用服务共同组成大模型技术生态。

5. Transformer：从文本到下一个 token

来源：第二讲第 80–94 页；第三讲第 19–33 页。

5.1 Tokenizer、Embedding 与位置

文本先经过匹配模型的预处理与分词，得到 token IDs；Embedding 层再查表得到向量。课件对比按词、按字符和子词分词：BPE逐步合并常见相邻单元，WordPiece按其词表学习 / 匹配规则形成子词，Unigram从候选词表中筛选子词。词表定义 token 与整数 ID 的对应关系，批次还可能需要 padding 和特殊标记。

第三讲第 19 页将 Tokenizer 与 Embedding 合并描述，本文拆开两步。Tokenizer 输出 ID，向量由模型的 Embedding 层产生；预处理也应遵循对应 tokenizer 的规则，不能把去停用词、词干化当成所有通用 LLM 的固定步骤。参见 Hugging Face Tokenization Pipeline。

Attention 本身不提供位置顺序，需要绝对位置、相对位置或 RoPE 等位置信息。原始正弦位置编码对位置 pos、偶数 / 奇数维度分别使用：

\[ PE_{pos,2i}=\sin\!\left(\frac{pos}{10000^{2i/d}}\right),\qquad PE_{pos,2i+1}=\cos\!\left(\frac{pos}{10000^{2i/d}}\right). \]

d 为表示维度；同一频率的一对正余弦可以用旋转关系表达位置偏移。RoPE 则把 Q、K 的成对维度按位置旋转，使点积体现相对位置。

5.2 Q、K、V 与缩放点积注意力

Q 表示“当前在找什么”，K 表示“可被匹配的信息特征”，V 表示“匹配后要汇总的内容”。自注意力中三者来自同一输入的不同线性投影。

\[ Q=XW_Q,\quad K=XW_K,\quad V=XW_V, \qquad O=\operatorname{softmax}\!\left(\frac{QK^{\mathsf T}}{\sqrt{d_k}}+M\right)V. \]

单头忽略 batch 时，Q、K 的形状为 L×d_k，V 为 L×d_v，注意力分数与权重为 L×L，输出为 L×d_v。L 是序列长度，M 是可选掩码；除以 √dₖ 控制点积尺度，Softmax 按可关注位置归一化。


图：第二讲第 85 页。投影、QKᵀ 与 AV 都涉及矩阵乘法。

多头注意力在不同子空间学习关系，再拼接并投影输出。头可以关注不同信息，但“每个头恰好负责一种固定语义”只是帮助理解的示意。

5.3 Block 的其他部分

模块 作用
FFN 对每个 token 独立进行特征变换，常由升维、非线性、降维组成
残差 x+F(x)，保留原始信息、改善梯度传播
LayerNorm / RMSNorm 调整特征尺度，帮助训练稳定
因果掩码 训练预测当前位置后续 token 时，禁止看到未来信息
输出线性层 将隐藏向量映射到词表大小的 logits
Softmax 与选择策略 得到候选 token 概率，并选出下一项

原始 Encoder-Decoder 的 Decoder 包含掩码自注意力及对 Encoder 输出的交叉注意力；不能把这种“双注意力”结构直接套到所有 Decoder-only 模型。

关键超参数是层数、隐藏维度、头数、FFN 中间维度和词表大小。Attention、FFN、参数存储和长序列中间张量是主要系统开销来源。课件还点到 MoE、FlashAttention、SSM / Mamba 等演进方向：MoE 用 Router 为每个 token 选择少量 Expert，增加总容量而控制每 token 激活计算，但也带来调度与通信问题。

6. MiniMind：把 Transformer 放到具体模型里

来源：第二讲第 96–104 页。以下配置均指课件中的 MiniMind-3 Dense 示例。

部分 课件给出的设计
整体 Decoder-only，小模型覆盖预训练、微调与强化学习链路
示例规模 64M 参数、8 层、隐藏维度 768
注意力 GQA，多个 Query 头共享较少的 KV 头
归一化 Pre-Norm + RMSNorm，课件还展示 Q/K 归一化
位置信息 RoPE；提及 YaRN 位置外推
FFN SwiGLU，课件示例默认不使用 Dropout

RMSNorm按均方根调整尺度，省去 LayerNorm 的减均值步骤，仍带有可学习缩放。GQA保留较多 Query 头，同时减少 KV 头数，从而减少 KV 存储；课件中把 KV repeat 到 8 个头是计算表示，不能据此认为缓存本身也必须存 8 份。

课件使用 [1,29,768] 的输入示例：29 个 token，每个 768 维；8 个 Query 头、每头 96 维，拼回输出仍为 [1,29,768]。RoPE 作用于 Q、K 来调整匹配关系，V 保留要汇总的内容。

SwiGLU 将输入分为 Gate 和 Up 两条投影，Gate 经过 SiLU，与 Up 逐元素相乘，再通过 Down 投影并接残差。SiLU 为 z·sigmoid(z)。

课件比较“深而窄”与“浅而宽”的小模型，在固定参数预算的相关实验中更看重深度，但也强调表示维度不能过窄；它给出的 512、1536 等经验阈值应放在具体示例中理解。

训练数据路线为 pretrain_t2t → sft_t2t → rlaif/agent_rl，受限资源下用 mini 数据组合或已有权重做实验。课件同时介绍 MiniMind-V、MiniMind-O、扩散语言与线性模型分支，以及 Hugging Face、ModelScope 这两个模型、数据和工具资源入口。项目结构与配置以课件所对应版本为准。

7. 预训练、微调与人类对齐

来源：第三讲第 35–38、46–49 页；V00 第 42 页。

7.1 各阶段在学什么

阶段 数据与目标
预训练 网页、书籍、对话等通用数据，以及代码、科学、多语等专用数据；学习通用语言与知识表示
SFT / 指令微调 人工或半自动构造的“指令—回答”示例，学习按要求完成任务
人类对齐 / RLHF 利用偏好反馈进一步调整回答行为；课件概括为初始训练、收集反馈、强化学习并迭代
提示与任务定制 用模板、示例和领域信息组织任务输入，不一定更新模型权重

课件将无人工标签的语言预训练归入广义无监督学习；更具体地说，预测下一个 token、预测遮挡内容等属于从数据自身构造监督信号的自监督学习。

预处理要考虑清洗、去重、格式统一与敏感信息处理。课件列出的预训练目标包括：自回归语言建模、只对后缀计损失的前缀语言建模、中间填充 FIM；模型学习什么，与损失计算覆盖哪些位置有关。

7.2 参数高效微调

方法 核心思路
LoRA 冻结原权重，用两个小矩阵表示低秩增量；推理时在适用情况下合并回权重
AdaLoRA 动态分配不同权重更新的秩预算
Prefix Tuning 在注意力的 K/V 前加入可训练连续前缀
Prompt Tuning 在输入表示前加入可学习的连续提示向量

设原权重 W₀ 为 d_out×d_in，低秩维度 r 远小于这两个维度，取 B 为 d_out×r、A 为 r×d_in：

\[ W=W_0+BA,\qquad P_{trainable}=r(d_{in}+d_{out}). \]

不同课件用 ABᵀ 或 BA 表达，本质由矩阵形状决定，不能只记字母次序。LoRA 主要减少可训练参数、梯度和优化器状态，基础模型权重与前向激活仍有开销。

8. 分布式训练：并行、显存与通信

来源：第三讲第 39–45 页；V00 第 33、41 页；V01 第 167–183、238–251 页。

8.1 三类并行与基本术语

并行方式 切分对象 主要代价
DP 数据并行 每卡相同模型，不同样本批次 同步梯度；普通 DP 不减少每卡模型副本
TP 张量并行 将同一层的矩阵 / 张量分到多卡 层内需要频繁通信
PP 流水线并行 按层或阶段切模型 传激活与反向梯度；负载不均和流水气泡
3D 混合并行 组合 DP、TP、PP 需要同时考虑负载、显存和拓扑

进程、Rank、Device、通信域不能混为一谈：常见映射是一进程一设备；Rank 是某通信组中的成员编号；通信域规定哪些成员一起做集合通信。逻辑上相邻的 Rank，不一定物理相邻。

模型装不下、每秒吞吐不足、总训练时间太长，是扩展多卡的不同动机。一般先利用机内高速互联，再考虑跨机网络；高频 TP 通信应尽量放在高速互联域内。

8.2 显存不只放权重

训练经历前向保存激活、反向计算梯度、优化器更新三个阶段。显存峰值还包括梯度、优化器状态、可能的 FP32 主权重、激活和临时 buffer。

以 7B 参数、十进制 GB 为例，按不同存储口径计算固定模型状态：

口径 每参数字节数 7B 模型状态，不含激活
只存 BF16 / FP16 权重 2 14 GB，仅权重
BF16 权重 + BF16 梯度 + 两份 FP32 Adam 状态 2+2+8=12 84 GB
上一行另加 FP32 主权重 16 112 GB
再将梯度由 BF16 改存 FP32 18 126 GB

V01 第 245 页的 84 GB 明确不含主权重与激活，第 230 页用经典 16 B/参数，第 207 页另举 18 B/参数的 126 GB。口径不同必须先拆账本，不能把这些数字当成同一配置下互相矛盾的总显存。

8.3 减少内存的手段

  • Gradient Checkpointing / 重计算：少存部分激活，在反向时重算，用计算换显存。
  • 混合精度：减少部分张量的字节数，同时关注数值稳定。
  • ZeRO：逐阶段分片优化器状态、梯度、参数，减少普通 DP 的重复保存。
  • Offload：把部分状态卸载到 CPU / 主机内存等，换来额外传输；课件同时介绍 ZeRO-Offload、ZeRO-Infinity。

DeepSpeed 提供相关内存优化和并行能力；Megatron-LM 侧重张量切分等大模型并行。选择方案时，既要看装得下，也要看通信与重计算是否拖慢训练。

8.4 梯度同步、Ring AllReduce 与扩展效率

同步 DP 中，各卡计算本地梯度，通过 AllReduce 汇总并按配置平均，再作一致更新。梯度可以分桶，边反向边通信；慢 Rank 和未被掩盖的通信尾部决定何时能更新。

N 张卡、每卡完整梯度大小 G 字节时，Ring AllReduce 包括 Reduce-Scatter、All-Gather，两阶段各 N−1 轮，每卡累计发送量：

\[ Q_{send}=\frac{2(N-1)}{N}G. \]

课件 8 卡、14 GB 梯度例子中，每卡发送 2×7/8×14=24.5 GB；这不是全系统所有卡的总流量，也不是发送与接收相加的双向总量。固定全局工作量下，计算可随加卡减少，每卡同步量却趋近常数，加速不会永远线性。

通信技术要区分层次：GPU 例子有 NVLink、GPUDirect、RDMA；昇腾例子中 HCCS 是硬件互联，HCCL 是集合通信库，跨机可走 RoCE。算法、链路、拓扑、拥塞与消息粒度共同决定通信代价。

9. 推理：加载、执行、缓存与解码

来源：第三讲第 51–57 页；V01 第 53–68 页。

9.1 通用推理流水线

模型加载 → 输入预处理 → 前向执行 → 输出解码。 加载时要对齐结构、参数键与 shape、dtype、设备、驱动和运行时；切到评估模式并按推理需要关闭梯度，随后预热，避免把首次编译与内存初始化混入稳定性能。

训练与推理应使用一致的输入约定。分类输出取 argmax / top-k；检测还要处理阈值与坐标，分割要恢复掩码，数值张量经过解码才成为任务结果。

Checkpoint、MindIR 等产物各有加载路径。分布式 Checkpoint 可按进程保存并在支持时重分片；Safetensors 保存张量权重，模型结构与配置另行提供，文件本身也可能分片。文件能读、参数能装载、模型行为正确，是三层不同的检查。

9.2 LLM 的 Prefill 与 Decode


图：第三讲第 52 页。两阶段的输入长度和复用方式不同。

阶段 计算与状态 主要关系
Prefill 并行处理提示中的多个 token，建立初始 K/V 缓存 影响首 token 时间
Decode 复用历史 K/V，为新位置计算 Q/K/V，通常每轮生成一个 token 影响后续 token 间隔

KV Cache 缓存的是各层历史 K、V。它减少重复投影与历史部分的重复计算，代价是随序列与并发增长占用显存；每轮新 Query 仍需要和可见的历史信息做注意力计算。

9.3 从 logits 选 token

策略 做法与取舍
Greedy 取最高分 / 最高概率 token，快，但可能单调或重复
Temperature 改变分布集中程度；温度越高，通常越分散
Top-k 只在最高概率的 k 个候选中，按重新归一化后的概率采样
Top-p 按累计概率阈值保留候选，再采样
Beam Search 维护多个高分候选序列，逐步扩展；比贪婪搜索覆盖更多路径，但成本更高

Top-k 是限制候选集合，不是要求在 k 个词中均匀随机抽取。自回归生成把选出的 token 加回上下文，再继续下一步。

10. 推理优化：每种方法在节省什么

来源：第三讲第 58–84 页；V01 第 161–164、231 页。

10.1 量化与低精度

量化用更低位宽表示权重或激活，减少存储与数据搬运，并在硬件、Kernel 支持时加速。QAT在训练中考虑量化影响，PTQ在训练后通过校准等方式完成量化。

对称量化常把实数零对应到整数零；非对称量化还使用零点偏移来适配区间。量化公式中的 scale、zero point 与通道 / 分组粒度都会影响误差与执行成本。

课件方法 重点
AdaQuant 逐层校准，减少量化层与全精度层输出的差异
BRECQ 按网络块重构，考虑跨层依赖，并利用二阶误差 / Fisher 信息近似评价重要性
LLM.int8() 向量级量化；异常特征维度走较高精度，其余走 INT8 的混合精度分解
CPU INT4 推理 量化算法、粒度、group size 与 INT4 Kernel / Runtime 协同；课件列出 GPTQ、AWQ、TEQ、SignRound 和 AVX2、AVX512、VNNI、AMX 等支持

勘误： 第三讲第 62 页的 BRECQ 引用了 AdaQuant 的论文，并将“240 倍”描述成模型速度。原论文是 Li 等人的 BRECQ，240 倍指相对相关 QAT 流程产出量化模型的速度，不代表推理吞吐提升 240 倍。参见 BRECQ 原论文。

10.2 Orca：把调度粒度降到每次迭代

静态批处理要求同批请求相互等待：短请求结束后占位，新请求也难插入。Orca 在迭代级重新组批，已结束请求退出，新请求进入，提高资源利用与响应效率。

课件的实现视角：Linear 等操作可合并 batch 与序列维度；Attention 则按请求组织各自的历史上下文，再合并结果。不同请求长度和阶段不同，不能简单当成完全相同的张量。

10.3 PagedAttention：减少 KV 内存浪费


图：第三讲第 73 页。借鉴操作系统分页思想，物理块无需连续分配。

为每个请求预留最大生成长度，会产生浪费和碎片。PagedAttention 将 KV 分成固定 token 数的块，用映射表连接逻辑块与物理块，按需分配和释放。

课件类比为：请求像进程，逻辑 KV Blocks 像虚拟页，物理 KV Blocks 像物理页，token 数据像页内字节。分页优化管理方式，不会消除保存 K/V 本身需要的字节数。

忽略并行切分，KV 缓存大小可按 2 × 层数 × 批次 × 序列长度 × KV头数 × 每头维度 × 每元素字节数 估算。课件的 40 层、KV 总维度 5120、FP16 示例，每 token 约 0.8 MB；它是该模型配置的数字，不能直接套到 GQA 模型。

10.4 StreamingLLM：保留“汇聚注意力”的初始位置

完整密集 Attention 的上下文成本高；只保留最近窗口又可能导致质量下降。课件介绍 Attention Sinks：初始少量 token 在注意力分布中起特殊作用。

StreamingLLM 组合初始 sink token 的 KV、最近窗口的 rolling KV，以及当前 token，并处理窗口位置与位置编码的对应。课件例子保留 4 个初始位置。能持续接收流式输入，不代表模型能检索已从窗口删除的任意遥远内容。

10.5 推测解码：小模型起草，大模型验证

草稿模型 q 连续提出 γ 个 token，主模型 p 并行核验；接受前缀，遇到第一个拒绝位置时按修正分布重新采样。一次主模型调用可输出 1 到 γ+1 个新 token。

课件的分布保持思路是：候选 x 按 min(1,p(x)/q(x)) 接受；拒绝后从归一化的 max(0,p−q) 分布补采样。接受部分贡献 min(p,q)，补偿部分贡献 p−min(p,q)，合起来仍是 p。保持分布依赖正确的接受与补偿规则，不能简单把大模型认为“不够好”的词随意替换。

10.6 FlashAttention：优化 IO，而非减少注意力语义

朴素实现把完整 L×L 注意力分数及概率矩阵写入 HBM。FlashAttention 对 Q/K/V 分块，结合在线 Softmax 和输出累加，在片上完成中间处理，减少 HBM 访问。

它与 PagedAttention 的侧重点不同：前者优化注意力计算的数据流和中间读写，后者优化服务中的 KV 分配和寻址。对精确密集 Attention，不能把减少中间存储误写成算术复杂度从 O(L²) 变为 O(L)。

11.2 vLLM：Scheduler、KV 管理器与模型执行器

课件中的 V1 主线是：加载模型并估算 KV 容量，初始化 Scheduler / KV Manager / ModelExecutor，按每轮 token 预算组织执行。运行中和等待中的请求、分块 Prefill、Decode 可以在调度中共同出现；资源不足时可能等待或抢占。

课件例子：3 个 prompt 长度为 3、5、12，每轮 token 预算为 10：

轮次 r1 / r2 / r3 的处理量 含义
Step 0 3 / 5 / 2 r1、r2 完成提示处理，r3 还剩 10 个 prompt token
Step 1 1 / 1 / 8 前两者 Decode，r3 继续 Prefill
Step 2 1 / 1 / 2 r3 完成剩余 Prefill
Step 3 1 / 1 / 1 三者共同 Decode

表中的数字是调度的 token 工作量，不能把 r3 的 8 个 Prefill token 误读为生成了 8 个输出 token。大模型还可按张量并行跨卡执行，KV 块由管理器按需分配和回收。

课件最后把挑战归为：长任务推理与协作、多模态与动态场景、高效推理与规模服务、智能体权限和提示注入、幻觉偏见隐私，以及持续评测与治理。知识点在于：可靠性要靠过程检查、失败恢复、权限控制、监测和反馈闭环共同实现。

12. CPU、GPU、FPGA、ASIC 与 DSA

来源：第一讲第 23、49–50 页；V01 第 90–111、184–200 页。

12.1 不同架构的分工与取舍

类型 主要特点
CPU ISA 定义指令、数据类型、寄存器与寻址等；擅长控制逻辑和低延迟串行任务，多级缓存缓解访存
协处理 / 扩展单元 如 AVX、AMX，为特定计算模式增加硬件支持
GPU 从图形固定管线发展到 CUDA 通用并行、SIMT 与 Tensor Core 矩阵加速；吞吐高，但仍有带宽、功耗和分支开销
FPGA 可重构硬件逻辑，在灵活性与定制效率之间取舍
ASIC 面向特定功能固化逻辑，通过驱动、CSR、表项与中断等交互
DSA 面向特定领域优化且保留一定可编程性，如 AI 的 TPU / NPU、网络领域的 P4 芯片

DSA 常利用领域并行、数据复用、适合任务的低精度和专用编译栈提高效率；挑战是新模型适配、性能与灵活性、生态建设、标准与跨平台迁移。不同芯片的核数量、功率和峰值并不直接构成同口径性能比较。

SIMD 表示一条指令同时处理多个数据元素；SIMT 用相同指令组织多个线程，课件 CUDA 例子以 32 线程组成 Warp。Tensor Core 等矩阵单元进一步支持矩阵乘累加与混合精度，不能把普通向量单元数量直接当成矩阵吞吐。

课件用 TPU 脉动阵列展示数据流：权重驻留处理单元，激活与部分和在阵列中传播，减少反复访问外部存储。GPU 的 Tensor Core、CPU 的矩阵扩展也说明通用与专用能力正在相互融合。

12.2 Host–Device 异构执行

在课件的分离式模型中，Host CPU 管控制和组织，Device 管密集计算，分别有主存与设备内存。一次任务通常是：拷入 → 下发 Kernel → 执行 → 同步 → 拷回结果。集成式 SoC 则可能共享内存，不能把独立显存和显式跨 PCIe 拷贝视为所有异构系统的必然形式。

Stream 是有序任务队列：同一队列按顺序执行，不同队列在依赖与资源允许时可并发。异步调用返回只代表已提交，使用结果前须确认完成。

小算子很多时，启动和下发开销可能大于实际计算；批量下发、CUDA / ACL Graph 与整图下沉用于减少交互。数据应尽量驻留 Device，必要拷贝成批组织，并与计算重叠。课件列出的昇腾接口包括 aclrtMalloc、aclrtMemcpy、aclrtCreateStream、aclrtSynchronizeStream。

13. 昇腾达芬奇架构：计算、存储与控制协作

来源：V00 第 30–39 页；V01 第 112–166 页。

13.1 从 SoC 到 AI Core

昇腾处理器内，AI Core承担密集矩阵 / 向量计算，AI CPU处理不适合 AI Core 的复杂算子，控制 CPU 与 TS 参与管理和任务调度；DVPP 负责图像视频预处理，外部接口与 HBM / DDR、L2 等提供数据通路。310、910 的课件示例规模不同，不宜混用其核数和存储规格。


图：V01 第 120 页，课件所示达芬奇 AI Core 组织方式。

单元 职责
Cube 矩阵乘加，是 MatMul 和卷积的主要计算资源；课件展示 16×16 分块
Vector 激活、归一化、逐元素计算、部分格式变换与非矩阵操作
Scalar 地址、参数、循环、分支与指令控制
MTE / DMA 数据搬运，部分路径支持随路类型或格式转换
Buffer / 寄存器 缓存输入、中间结果与累加结果，支撑复用

课件还介绍矩阵 A 按行、B 按列的分块存储，以及“大 Z 小 Z / 大 Z 小 N / 大 N 小 Z”等布局记号。记忆重点是：逻辑矩阵形状相同，物理分块布局可以不同，布局要匹配计算单元的取数方式。

13.2 Buffer 层次与 AIV / AIC 路径

按课件 910B2 示例，L0A / L0B 各 64 KiB、L0C 128 KiB、UB 192 KiB、L1 512 KiB、L2 192 MiB，另有 BT 等特定用途 Buffer。数值是示例型号约束，实际开发需查目标平台。

  • AIV 路径：CopyIn 到本地输入队列 → Vector Compute → 输出队列 → CopyOut。
  • AIC 路径：矩阵从 GM 进入本地存储 → 分块与格式转换 → Cube 计算 → 中间结果累加 / 后处理 → 写回。
  • 逻辑位置核对：A1 / B1 对应 L1，A2 / B2 对应 L0A / L0B，CO1 对应 L0C；CO2 的具体落点与实现有关。

V01 第 143 页把 A1 / A2 等直接标成 L2 / L1 cache，容易与物理层次混淆。上文按 Ascend C 官方术语表修正。AIC / AIV 在分离架构中分别表示 Cube Core / Vector Core，不能把所有型号都当成完全相同的内部结构。

13.3 并发流水线与同步

标量、矩阵、向量和存储转换队列可并发；顺序发令不表示不同执行单元天然按代码顺序完成。SetFlag / WaitFlag 等同步机制保证数据已就绪，再让依赖它的流水线继续。

课件的三个场景：

  1. MatMul + LeakyReLU：Cube 做矩阵计算，Vector 做逐元素处理，跨核接力需同步。
  2. Conv + BN + ReLU：推理时固定统计量的 BN 可折叠进卷积参数，再结合激活融合，减少中间读写与启动；具体能否自动融合取决于模式和实现。
  3. FlashAttention：Cube 计算 QKᵀ、AV，Vector 做缩放 / Softmax，Scalar 管理循环与同步，并通过分块重叠执行。

13.4 HBM、Tiling 与双缓冲

HBM 用 TSV、堆叠 DRAM 与近计算芯片的高密度封装提供宽接口。课件从 HBM2、2E、3、3E 讲到 HBM4 的带宽、容量、通道与能耗演进；产品与路线图参数应分别理解，核心问题是带宽增长和算力增长不总匹配。

Tiling 将大矩阵切成能放入片上存储的小块，追求时间复用与空间复用；大 Tile 复用好但占空间，小 Tile 有利并行却可能增加搬运。边界与对齐还可能需要补零、转置、格式转换。

Double Buffer 用两组缓冲交替工作：计算当前块时预取下一块，隐藏部分搬运时间。代价是占更多片上容量，还要确保队列和同步正确；异步搬运并不意味着等待一定能完全消失。

GPU 也有软件管理的 Shared Memory，不能一概说“GPU 自动、NPU 手工”。 课件比较的重点是昇腾算子开发中显式 Buffer、MTE 和同步的突出地位。普通 CUDA Shared Memory 的共享范围是同一 thread block 内的线程；第 163 页“供多个 thread block 共享”的表述应附加特殊机制条件，参见 NVIDIA CUDA 文档。

14. 开销估算、Roofline 与关键路径

来源：V01 第 201–237 页。

14.1 先区分模型规模与运行规模

N 层、隐藏维度 d、FFN 中间维度 dff 决定主体权重；批次 B、序列长度 L 决定一次输入和激活规模；精度决定每个元素占多少字节。

对课件采用的标准多头 Attention、两层非门控 FFN，忽略偏置与 Norm：

\[ P_{layer}\approx4d^2+2d\,d_{ff},\qquad F_{fwd,layer}\approx8BLd^2+4BL^2d+4BLd\,d_{ff}. \]

这里一次乘加计 2 FLOPs；主体参数按层累计，还要另计词嵌入 / 输出层。若 dff=4d，每层参数约 12d²，前向约 24BLd²+4BL²d。GQA、SwiGLU、MoE 不能不改结构假设就套用这些系数。

短序列时投影与 FFN 往往更重；L 增加，Attention 关系项按 L² 增长，其与主体矩阵乘的相对量在该假设下约为 L/(6d)。长序列不仅增加运算，也增加中间结果与 IO 压力。

常规稠密 Transformer 的粗略训练预算是 C≈6PT，P 为参数量，T 为训练 token 总数；前向约 2PT、反向约 4PT。它忽略部分注意力平方项、重计算、通信等，用于早期估算；训练时间要除以有效吞吐，不能直接除硬件标称峰值就当成实测时间。

14.2 Roofline：算力上界与带宽上界

设算术工作量 W 为 FLOPs，显存搬运量 Q 为字节，算术强度 I=W/Q；硬件峰值算力为 Ppeak，所选层次的带宽为 Bmem：

\[ P\le\min(P_{peak},I B_{mem}),\qquad I^*=P_{peak}/B_{mem}. \]


图：V01 第 210 页。图中数字属于课件选定的硬件口径，方法本身可用于其他平台。

I 低于脊点 I* 时常受带宽约束，提高复用可提升上界；高于脊点后受算力上界限制。显存容量回答装不装得下，显存带宽回答数据送得够不够快，两者必须分别检查。

14.3 Hockney、重叠与关键路径

一次消息传输可近似为 α+nβ，α 是固定启动时延，β 是每字节传输耗时。若集合通信共 s 轮、累计传 n 字节，则近似 sα+nβ。小消息更容易受启动时延影响，大消息更容易受带宽影响。

计算、访存与通信并非总按顺序发生；端到端时间由依赖链中最长的关键路径决定。通信与反向重叠后，只有未被隐藏的部分继续延长 step。

课件的瓶颈诊断流程是：定义负载和计时边界 → 计算工作量与搬运量 → 建立性能模型 → 对照真实依赖链 → 改一项并端到端复测。增加片上复用、重计算、压缩、并行都会转移成本，必须保持输入、精度、预热和起止边界一致，才能比较净收益。

15. 在线推理指标：吞吐、延迟与饱和

来源：V01 第 253–269 页。

一次模型前向耗时，不等于用户等待时间。 完整链路包括网络接入、预处理、排队调度、Prefill、Decode 和结果传输。

指标 定义与注意事项
TTFT 请求提交到第一个输出 token 返回，通常含排队、Prefill、网络等
TPOT 第一个输出 token 后，相邻 token 的平均时间间隔
E2E 完整请求的端到端延迟
P95 / P99 描述慢请求尾部的分位数，不能只看平均值
TPS 单位时间处理 / 生成的 token 数，要注明输入、输出或合计
RPS 单位时间成功完成的请求数，与每次生成多少 token 不等价
并发数 / Batch Size 前者是系统中同时存在的请求规模，后者是一批参与执行的请求数

若输出 token 数为 Nout>1，在课件一致的测量口径下：

\[ TPOT=\frac{E2E-TTFT}{N_{out}-1},\qquad E2E=TTFT+(N_{out}-1)TPOT. \]


图：V01 第 264 页。更高并发不一定带来更高有效吞吐。

排查时先判断是否饱和：TTFT 高看接入、排队、Prefill；TPOT 高看 Decode 执行与数据供给；OOM / 显存持续增长看 KV 容量和调度；同时观察 TPS、RPS、P95/P99、错误率和设备利用率。

17. 快速自测、易错点与课件索引

17.1 六个问题贯穿全课

  1. 模型在算什么？ 把层展开为张量、矩阵乘、归一化、激活、重排与依赖。
  2. 训练比推理多了什么？ 梯度、激活保留、优化器状态，以及参数更新。
  3. 为什么加卡不一定更快？ 通信、慢卡、流水气泡、拓扑和同步限制扩展。
  4. 为什么参数少不一定运行快？ 真实时间还受 Kernel、布局、带宽和调度影响。
  5. Prefill、Decode 为什么要分别看？ 两者处理的 token 数、计算复用和主要指标不同。
  6. 怎样证明优化有效？ 同一负载、精度、预热与计时口径下，先验证正确性，再比较端到端结果。
