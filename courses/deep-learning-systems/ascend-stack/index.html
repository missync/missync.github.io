深度学习系统：昇腾技术栈

本文最后更新于 2026年10月30日 凌晨

1. 平台与调用路径

昇腾 NPU 是计算底座，Atlas 用模块、板卡、小站、服务器与集群覆盖端、边、云。课件举例包括 Atlas 200DK、200I A2、500 A2 和 800T A2；型号对应不同的开发、推理或训练场景。

模型任务的基本路径是 应用 → 框架与适配 → CANN → Runtime / 驱动 → NPU。PyTorch 通过 torch_npu 适配昇腾，MindSpore 提供另一条框架路径。

1.1 CANN 内部承担什么

  • 图与编译：处理计算图、优化与算子映射，生成适合设备执行的任务。
  • 算子实现：由算子库或自定义算子提供计算，Ascend C 用于 AI Core 算子开发。
  • 运行管理：设备内存、任务下发、流与同步，让计算按依赖完成。
  • 集合通信：HCCL 提供 AllReduce、Broadcast 等通信原语。

HCCS 是硬件互联，HCCL 是通信库。框架定义模型和梯度，编译与算子层实现计算，运行时安排实际资源，不能把这些职责都归给模型代码。

1.2 开发、训练和推理工具

工具 主要用途
MindStudio 工程开发、编译调试与性能剖析
MindSpeed 大模型训练的计算、内存、通信及并行优化
MindIE 模型推理执行与服务
ATC 模型转换与离线编译
AscendCL 应用侧设备、内存与模型执行接口

这些组件并非必须依次经过的一条流水线；训练、离线推理与服务部署按实际路径组合。

2. 从模型运行到算子开发

2.1 先跑通框架侧

先确认驱动、CANN、框架和适配层配套，再核对设备可见性、张量 shape / dtype 与前后处理。框架构建前向和反向计算，分布式训练还要在梯度同步后执行优化器更新。

2.2 Ascend C 算子的执行主线

一个典型分块算子按 CopyIn → Compute → CopyOut 组织：搬入输入，执行计算，写回输出。Cube 主要做矩阵乘加，Vector 处理逐元素操作，Scalar 组织地址与控制。

Tiling把输入划分成适配片上存储的块，还要考虑核间分配、边界与对齐。Double Buffer用两组缓冲轮换，让当前块计算与下一块搬运重叠，需要额外容量及正确同步。

更详细的 AI Core、Buffer 与事件同步见算力架构与性能分析。

2.3 性能优化闭环

MindStudio 的流程可概括为 创建工程 → 编译链接 → 运行调试 → Profiler 剖析。从时间线和算子数据确定主导瓶颈，再调整 Tiling、双缓冲或融合，最后用相同负载复测数值结果与端到端时间。

3. 大模型训练与适配

DP 切样本，TP 切层内张量，PP 切网络阶段，三者可以组合。MindSpeed 从计算、内存、通信和并行组织等方面优化训练；收益取决于模型结构、显存与互联拓扑。

LoRA冻结基础权重，只训练低秩增量，主要降低微调状态开销；量化减少权重或激活的位宽，主要影响存储、搬运和支持低精度的计算。二者作用不同，原理见大模型训练、推理与服务。

4. 模型转换与推理部署

4.1 ONNX → ATC → OM → AscendCL

  1. 导出：从训练框架导出模型，明确输入名称、shape、dtype 与预处理约定。
  2. 转换：ATC 完成图优化与算子映射，生成与目标平台匹配的 OM 离线模型。
  3. 验证：用 msame 等工具加载 OM，执行离线推理；将结果与原框架对照，定位转换、输入或数值差异。
  4. 集成：通过 AscendCL 管理设备、内存、模型加载、执行与资源释放，接入业务前后处理。

ATC 负责转换，msame 用于推理验证，两者角色不同。

4.2 大模型服务与端侧应用

MindIE 路径关注模型加载、推理执行、请求接口、并发与资源配置。不能把所有大模型服务都等同于 ONNX / OM 离线模型路径；应按目标模型和组件版本选择适配方式。

云端侧重吞吐和多请求调度；端侧受内存、功耗与离线条件制约。部署后还需做版本管理、健康监测与质量检查，并用一致的输入 / 输出长度统计服务指标。

5. 课程实验如何串起全栈

课件把实践分为四个模块、十个实验：

  1. 基础流水线（实验 1–3）：PyTorch 训练推理 → CANNLab 环境检查 → PyTorch + torch_npu 开发运行。
  2. 算子开发（实验 4–5）：Ascend C 典型算子 → MatMul Tiling 与 Double Buffer 优化。
  3. 大模型训练（实验 6–7）：集群混合并行 → LoRA 参数高效微调。
  4. 推理部署（实验 8–10）：ONNX / OM 转换部署 → MindIE / AISBench 并发压测 → 端侧推理应用。

每步保留可复现的源码、配置、正确性基线及性能结果，形成“模型能运行 → 能定位瓶颈 → 能验证优化”的实践链路。

课件对应：《第一讲：课程概述》52–74 页；《V00-课程导学》26–48 页。工具定位按课件整理，版本配套与型号支持应在实际实验时核对。
